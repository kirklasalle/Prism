0 · Executive Summary

The Model Matrix is Prism's brain-stem: it maps every reachable model — from a 1B local Gemma to a trillion-parameter frontier cloud model — to a capability profile, and routes each task (and each Spectrum Refraction hemisphere) to a model.

The engineering underneath is strong: tiering, modality routing, deprecation lifecycle, VRAM-awareness, SR isolation invariants, and a kinship model to prevent cognitive homogenization. But it optimized for one axis only: capability tier. It was tier-maximizing, not value-aware. Cost lived in a separate, stale catalog with its own duplicate tier field.

Today the Matrix answered "what is the best model?"
Now it answers "what is the best model for this budget, this task, and this refraction — and what do I gain or lose by spending more or less?"

2 · Critical Audit Findings

# Sev Finding
F1 critical No cost dimension in the routing brain. The only budget lever (eco) drops a whole capability tier instead of finding a cheaper model at the same tier.
F2 critical Two sources of truth for tier — capability matrix vs pricing catalog, already diverging.
F3 critical "Suggest" returns a point, not a spectrum. Both paths return the maximal pick, no cost annotation, no trade-off framing.
F4 major SR "Creative" required media-generation modality — disqualifying nearly all text models and killing budget refraction.
F5 major Pricing catalog stale & silently zeroing — any lookup miss returns cost 0, conflating "unknown" with "free."
F6 major powerMode is a 3-way toggle, not an Economy→Frontier spend spectrum.
F7 moderate No value / efficiency metric — "cheap" and "good value" are different questions.
F8 moderate Cost preview is SR-only and coarse — no Primary-path per-turn estimate.
F9 moderate Isolation suggestion is not budget-aware.
F10 moderate Unknown-model fallback defaults to mid-tier cloud with no cost — expensive unknowns look free.

3 · The Vision — The Refraction Spectrum

Prism already refracts a prompt through a spectrum of cognition (Logic / Creative / Primary). The Matrix now refracts model choice through a spend spectrum — two orthogonal axes. Kirk's correction was exactly right: a full spectrum from cheapest to money-no-object is just numbers, dates, percentages and easy math. That math now lives in model-spectrum.ts.

4 · New Data Model — One Profile, Two Axes

Pricing is merged into the capability profile (kills F2), with cost + value fields (kills F1/F7):

interface ModelCapabilityProfile {
  /* …existing capability fields… */
  costInputPer1M?: number;      // USD; 0 = truly free
  costOutputPer1M?: number;
  costKnown?: boolean;          // false ⇒ "unknown", NOT "free"  (fixes F5)
  billingModel?: "per-token" | "subscription" | "local-free" | "unknown";
  pricingVerifiedAt?: string;   // ISO date  (the "dates" Kirk means)
  budgetClass?: BudgetClass;    // economy | value | balanced | premium | frontier
  qualityIndex?: number;        // 0-100 price-independent capability
  valueScore?: number;          // 0-100 quality-per-dollar
  latencyClass?: "instant" | "fast" | "standard" | "slow";
}

6 · Value Score — the "Smart Money" Signal

The knee of the price/quality curve, so budget bands pick good value, not merely cheapest: 

qualityIndex = tier×18 + strengthBonus + contextBonus          // 0-100, price-independent
priceFactor  = 1 / (1 + blendedCostPer1M)                      // → 1 as cost → 0
valueScore   = round(100 · quality/100 · priceFactor^α)        // α tunes price sensitivity
Economy · Value · Balanced
rank by valueScore — best bang-per-buck above the floor.
Premium · Frontier
rank by qualityIndex — spend for capability; value is secondary.
