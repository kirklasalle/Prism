System Architecture

The technical blueprints of Prism's dual-hemisphere isolation and coordination framework.

PIPELINE: SPECTRUM REFRACTION EXECUTION FLOW

1. Dynamic Task Splitting

When a user request enters the system, the routing middleware inspects active query tags and file structures. Rather than running a monolithic generation cycle, the task is split:

  • Analytical scripts, API schema integrations, logic flows, and unit-testing definitions are packed for the Logic Hemisphere.
  • Visual systems, user interface designs, color palettes, animations, and typography configurations are targeted for the Creative Hemisphere.

2. Instance Isolation & Kinship

A crucial part of Prism Refraction is avoiding cognitive echo. If the Left and Right hemispheres use the same model family, they inherit identical reasoning biases, neutralizing the value of the split.

Prism performs validation on the Kinship Matrix. If models belong to the same family, the system flags the issue and automatically adjusts temperature parameters or dynamically assigns a different sub-model to keep outputs distinct.

3. Aggregator & Governance Audit

The Coordinator collects outputs from the parallel runs, injecting its own contextual directives to unify the files. Before writing anything to the local workspace, the output passes through the verification pipeline:

AST Analysis

Validates Abstract Syntax Trees to guarantee that bracket matching, module imports, and function signatures are intact.

Layered Security Architecture

Security priority begins at the foundation of the codebase and enforces trust at every layer up.

LAYER 0: FOUNDATION LEDGER

Core Cryptographic Ledger

Every tool execution, workspace modification, and cognitive reasoning step is logged on a tamper-evident, SQLite-backed audit ledger. Entries are linked to the active Character Accountability Chain (CAC) and store full SHA-256 pre-and-post diff checksums.

DRILL DOWN →
LAYER 1: POLICY ENGINE

3-Tier Authority Gates

The policy engine processes every action against risk matrices. Tier 1 (reads) runs instantly, Tier 2 (basic edits) evaluates state constraints, and Tier 3 (terminal shell execution, network diagnostic tests) halts execution for human approval.

DRILL DOWN →
LAYER 2 & 3: RUNTIME ENFORCEMENT

Preamble Injection & Guardian

The 10 Laws (PAD) are injected directly into LLM system prompts inside XML tags. In parallel, the Guardian Agent (powered by local llama.cpp) executes an offline task every 10 minutes to verify the SHA-256 hash integrity of the PAD.

LAYER 4 & 5: REPOSITORY & BUILD PROTECTION

Boot & CI/CD Gating

Prism prevents silent configuration bypasses. At boot, DashboardService checks the local PAD hash. In the cloud, CI Gate 9 blocks merges or package releases if the directives file has been modified without matching updates to compilation constants.

LAYER 6: HOST ISOLATION

Sandbox & Tool Sandboxing

All browser automation sessions are handled through Playwright with strict environment limits. Terminals are virtualized through custom PTY channels, and all disk writes are restricted to the workspace folder, isolating host operating systems.

DRILL DOWN →
LAYER 7: IAM & ENTERPRISE SSO

Identity Management & RBAC

Authentication is protected by timing-safe token checks. Enterprise installations integrate SSO (OIDC/SAML) and SCIM v2 automated user provisioning. Roles are verified dynamically against a detailed RBAC schema prior to granting session overrides.
