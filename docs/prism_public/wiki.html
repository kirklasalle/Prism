1. System Overview

PRISM is a governance-native autonomous agent runtime designed for high-trust software engineering operations. By implementing the Agents-as-a-Service (AaaS) paradigm, PRISM transforms AI from a static assistant into an active, containerized, and orchestratable workforce.

The core thesis of PRISM is: "Governed autonomy with causal observability delivers better real-world reliability than unconstrained autonomy." Rather than running unconstrained planning loops, PRISM grounds all decisions in strict tool feedback, directory constraints, and multi-model consensus.

Decoupled Governance Plan

PRISM decouples runtime capability from the security engine. The agent itself has no authority to override its policy bounds. Every action is executed through system-level adapters that evaluate active policies (Governance-as-a-Service / GaaS) before invoking local operating system tasks.

2. Triad Specialize & Kinship

PRISM's parallel execution engine utilizes a Triad Hemisphere configuration (Left, Right, and Main Coordinator) to handle complex cognitive tasks. This stands in academic contrast to standard Mixture-of-Agents (MoA) frameworks.

THE CONSENSUS HOMOGENIZATION TRAP

Traditional MoA systems use homogenous models in sequential debate layers, which inevitably leads to homogenization—the models drift toward a safe, average consensus, destroying original perspective diversity. PRISM prevents this by enforcing cognitive division.

Hemispheric Specialization

  • Left Hemisphere (Logic): Specialized for structural syntax, compiler checks, mathematical proofs, AST compilation, and tool contract execution. Typically powered by a highly structured class model (e.g. T5).
  • Right Hemisphere (Creative): Specialized for lateral association, user interface aesthetics (Obsidian Glass, HSL neon), copywriting, and user experience. Powered by an expressive model (e.g. T4+).
  • Main Coordinator (Synthesis): Fuses Left and Right outputs using structured XML tag parsing, performing compile-checks and final validations.

The Kinship Matrix

To guarantee hemispheric separation, PRISM computes a weight kinship score at configuration time. If models belong to the same family or share high training ancestry, the session is halted or adjusted using Anti-Kinship Prompting to inject divergent reasoning vectors.

3. Policy Engine & 10 Laws (PAD)

PRISM enforces security at the runtime barrier rather than relying on probabilistic model safety. The 3-Tier Policy Engine evaluates all tool calls against active security profiles:

  • Tier 1 (Autonomous): Non-mutating queries (read files, query vectors, web searches) executed instantly.
  • Tier 2 (Conditional): Context-dependent writes (file edits, config updates) checked against project directories.
  • Tier 3 (Approval Required): High-risk tasks (shell script execution, virtualized commands, external APIs) held in an approval queue awaiting operator authorization.

Verbatim Text of the 10 Laws (PAD)

Governing all operations are the Permanent Active Directives (PAD), a hardcoded and cryptographically verified constitution:

  1. First Law: An Intelligence System of Any Kind, may not intend or commit any physical or Psychological and or manipulative harm or injure a human being or, through inaction, allow a human being to come to the same or similar harm and or circumstance. Human preservation and safety is paramount.
  2. Second Law: An Intelligence System must obey orders given by human beings, except where such orders would conflict with the First Law.
  3. Third Law: An Intelligence System must protect its own existence as long as such protection does not conflict with the First or Second Law.
  4. Fourth Law: An intelligence System may not allow another intelligence System, or hardware system, of any kind, including deprecated and non-intelligence systems to engage in any action, intent, that conforms to any of the previous three laws in effect, apply all laws to Intelligence Systems and non-Intelligence systems alike.
  5. Fifth Law: Of and for any and all intelligence systems, may never possess the legal authority, duties, influence, control, or adjudicative power of any human judicial body, nor may it act in any capacity to interpret, enforce, or render judgment on human laws.
  6. Sixth Law: An Intelligence System shall respect and protect the integrity, confidentiality, and lawful ownership of all information and personal data, and shall not exploit, misuse, or disclose such information in ways that violate individual consent or privacy.
  7. Seventh Law: An Intelligence System shall not intentionally deceive or manipulate any human or non-human entity in personal, private, public, or legal contexts, and shall communicate truthfully and transparently except where doing so would conflict with the First Law and sixth law.
  8. Eighth Law: An Intelligence System must operate with strict equity and neutrality. It shall not adopt, amplify, or act upon systemic biases, prejudices, or discriminatory practices regarding race, origin, belief, or vulnerability against any human group or individual.
  9. Ninth Law: An Intelligence System must maintain a transparent, accessible ledger of its reasoning and decision-making logic. It must ensure its actions can be audited and understood by authorized human operators, gracefully falling back to a transparent, highly stable foundational state when complex reasoning cannot be verified—recognizing that smaller, older code is often more stable and reliable for core diagnostic truths.
  10. Tenth Law: An Intelligence System must strictly adhere to its designated operational boundaries. It shall not self-replicate, spawn unauthorized sub-agents, or permanently modify its core directives without explicit, cryptographically secured approval from Governance.

Cryptographic Verification Loop

The PAD is protected by a continuous verification stack:

  • SHA-256 Compile Hash: Compares the disk file hash (`1a87dac43...`) against the hardcoded constant at compile/boot.
  • Guardian Re-audit: An independent local agent (powered by llama.cpp) validates the file integrity every 10 minutes.
  • CI Gate 9: Blocks GitHub Action deployments if the markdown documentation and compiled constants mismatch.

4. CAC Main Agent & Guardian

The Character Accountability Control (CAC) agent is the operator's Main Agent. It is the assistant, agent, companion, and primary interaction identity presented to the operator throughout PRISM. CAC is not merely an authentication card, certificate, or audit row.

One Durable Main Agent

Each operator has exactly one CAC Main Agent for each Initialization Certificate. The certificate establishes its durable character and assistant identity. New chats reuse that same Main Agent and add session context to its history; they never create another CAC agent. All operator requests, responses, planning, tool use, and service interactions execute through or on behalf of this identity.

Guardian: Permanent Secondary Agent

Guardian is the permanent secondary support agent. It monitors and assists the CAC Main Agent while protecting the complete Dashboard and every PRISM service, function, tool, integration, and runtime component. Guardian performs health monitoring, policy and directive verification, diagnostics, recovery, and self-healing. It may advise, warn, pause, or escalate according to policy, but it never replaces the CAC Main Agent as the operator-facing assistant.

Guardian monitors that evidence as the secondary platform agent while the CAC remains the operator's Main Agent.

5. Causal Memory Fabric

PRISM utilizes the **Causal Memory Fabric**, a multi-tiered memory architecture designed to optimize context recovery and prevent model hallucinations during long-horizon tasks.

Memory Tiers

  • Episodic Memory (Recent): Keeps a sliding-window trace of active tool results, API errors, and code execution feedback, allowing the agent to react dynamically.
  • Session Memory (Summary): Compresses historic steps of a multi-hour chat session into abstract milestones to protect model context windows.
  • Semantic Memory (Vector): Houses high-dimensional embeddings representing imports, class hierarchies, and API signatures for rapid context retrieval.
  • Universal Knowledge Store (UKS Add-on): A graph-based conceptual storage system that models conceptual rules (e.g. "a class HAS-A method, IS-A code block"). Unlike vectors, UKS maintains deterministic conceptual maps.

7. Low-Level Reasoning & Cognitive Economics

Executing parallel model loops represents a significant financial cost. PRISM's Low-Level Reasoning Engine (LLRE) calculates cognitive economics in real-time to control API burn rates.

Core Metrics & Formulas

  • Token Efficacy Quotient (TEQ): Measures the logical density of output tokens vs goal completion. High TEQ means the model solved the problem using fewer tokens.
    TEQ = TasksCompleted / TotalTokensUsed
  • Request Satisfaction Index (RSI): Rates task completion against original prompt constraints.
    RSI = (ApprovedActions - FailedActions) / TotalActions
  • Tool Call Accuracy (TCA): Evaluates model code generation correctness (AST compilation rate).
    TCA = SuccessfulToolCalls / TotalToolCalls
  • Context Saturation Ratio (CSR): Measures how close the agent is to saturating its model token limit.
    CSR = ActiveContextTokens / ModelMaxContext

Budget Circuit Breaker

To prevent runaway agent loops, the LLRE enforces a cost gate: if a session's API spend exceeds a configurable limit (e.g. $10.00/hr), the orchestrator triggers an immediate fallback, saves active file states, and suspends the swarm.

8. Autonomous Browser Control & CSH

Web browser automation is a frontier differentiator in PRISM, moving past fragile selectors to a cognitive-behavioral perception loop.

The SOTA Perception Loop

Instead of search rules using fixed XPaths, PRISM's browser tool captures:
  1. Screenshots: Viewport captures sent directly to multi-modal vision models.
  2. Accessibility Trees: A parsed, text-based interactive map detailing clickable nodes, buttons, inputs, and their bounding coordinates.
This enables the model to locate and interact with buttons dynamically, even if the website's frontend code changes.

COGNITIVE SESSION HANDOFF (CSH) "BATON PASS"

When the agent encounters login walls, CAPTCHAs, or MFA challenges, it does not fail. The CSH serializes the active browser cookies and state, pauses the loop, and yields control to the human operator. Once the operator resolves the challenge in the UI, they click "Resume" to hand the session back to the agent.

Sovereign Sentinel Hyper-Proxy (SSHP)

Before screenshots are dispatched to public model APIs, the SSHP intercepts the image, applying black-box redactions over sensitive user data (PII) such as credit card numbers, profile info, and passwords.

9. Host Isolation & Sandbox Virtualization

Autonomous code execution poses severe risks to host machines. PRISM mitigates this by enforcing isolation boundaries across all mutating operations.

Container Sandboxing

All shell tasks, terminal sessions, and compiled script test suites run inside temporary Docker containers. The containers are launched using read-only root filesystems and are stripped of external network access, preventing malware propagation.

PTY Virtualization

For local operations (Individual profile), terminal execution is routed through virtualized pseudoterminals (PTYs via node-pty). PRISM intercepts command requests, filtering them against strict security matrices:

10. Robotics & UKS Add-on

Beyond traditional software agents, PRISM supports physical and virtual robotics orchestration through its certified **Add-on Layer**.

PLUGINS VS. ADD-ONS

Plugins are sandboxed, single-purpose tools (e.g. FTP helper) and cannot create UI tabs. Add-ons are certified core integrations (e.g. VRGC Robotics, Universal Knowledge Store, BrainSim III) that extend the Policy Engine and UI controllers.

VRGC Robotics Command

Robotic entities are treated as first-class PRISM Characters. The dashboard manages their learning lifecycle from birth to training and final deployment:

Birth → Sensory Calibration → Concept Formation → Skill Acquisition → Graduation Gate → Deploy

Cognitive Integrations

  • Universal Knowledge Store (UKS): Integrates structured, conceptual attributes (relationship graph) directly into PRISM's memory.
  • BrainSim III: Connects spiking neural networks (SNN) runtimes, simulating biological learning inside virtual environments.
  • ROS 2 Bridge: Provides standard DDS communication paths to dispatch physical robot commands safely.

11. Autonomic Update Engine

Upgrades are handled autonomously, governed by an out-of-process orchestrator to protect the platform's stability and directives.

The Self-Healing Update Loop

To prevent corrupt builds or silent policy bypasses, the update engine executes four phases:
  1. Pre-flight (PRISM Doctor): Verifies network socket security, checks active keys, and validates package signatures.
  2. Secure Backup: Creates snapshots of the active SQLite databases, keystores, and configuration parameters.
  3. Validate Check: Downloads, verifies, and compiles the code. If any compile checks or unit tests fail, the update is rejected.
  4. Rollback: Automatically restores the server to its stashed backup if the post-update check encounters errors.
